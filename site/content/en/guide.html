murmur guide

Everything to add murmur to a site, choose how the AI is called, index your pages and use the npm package.

Quick start

Paste this line before </body> on every page of your site:

<script type="module" src="https://maxgfr.github.io/murmur/cdn/murmur.js"></script>

A bubble appears in the bottom right corner. Without any option, it answers from the text of the page the visitor is reading, and each visitor uses their own AI key. To answer from the whole site, build an index (see Index your site); to spare visitors the key, use a proxy (see AI models and keys).

The configurator on the home page writes the line for you.

Options

Every option is a data- attribute on the script tag. All are optional.

AttributeWhat it does
data-indexURL of the index file written by murmur index, for example /murmur-index.json. Without it, the widget reads the current page.
data-endpointURL of your OpenAI-compatible proxy (https). Visitors then chat without a key.
data-providerProvider preselected for visitors who bring their own key: openai, anthropic, google, mistral, openrouter, groq…
data-modelModel id: the one preselected for visitors, or the one asked of your proxy.
data-instructionsYour instructions to the assistant: who it is, its tone, what it should not discuss.
data-title, data-greeting, data-placeholder, data-buttonThe panel title, the first message, the question field's placeholder and the bubble's label.
data-langLanguage of the interface and the answers: en or fr. By default, the page's lang, then the browser's.
data-positionbottom-right (default) or bottom-left.
data-accentAny CSS colour for the bubble, the header and the visitor's messages.
data-themeauto (default, follows the system), light or dark.
data-opentrue opens the panel on load.
data-storage-keyPrefix of what the widget stores, to keep two widgets on one domain apart.

Index your site

The index is a JSON file of your pages cut into passages under their headings. Build it from your site's output folder, after your static site generator:

npx murmur-rag index ./dist --out ./dist/murmur-index.json

It reads every .html, .md and .txt file. In HTML it keeps the content of main (or article, or body) and skips navigation, headers, footers, forms and scripts. Add data-murmur-ignore to any element you want left out.

OptionWhat it does
--outWhere to write the index (default murmur-index.json).
--baseURL prefix of the pages, for a site served under a sub-path such as /docs/.
--rootCSS selector of the content in each page.
--excludeCSS selectors to skip, on top of the defaults.
--max-chunkLongest passage in characters (default 2000).

The command also takes a live site: npx murmur-rag index https://example.com/sitemap.xml fetches every page of the sitemap.

In a GitHub Action

Add one step after your build, before uploading the Pages artifact:

- run: npx murmur-rag index ./_site --base /my-repo/ --out ./_site/murmur-index.json

AI models and keys

A key written in a web page can be read by anyone, so murmur never asks you to put one there. Pick one of two ways.

Your proxy holds the key

Deploy the example Cloudflare Worker. It keeps your key as a secret, forwards chat requests to any OpenAI-compatible API (OpenRouter, OpenAI, Groq, Mistral…), accepts only your site's origin, fixes the model and caps the length of each answer. Then:

<script type="module" src="https://maxgfr.github.io/murmur/cdn/murmur.js"
  data-endpoint="https://murmur-proxy.you.workers.dev/v1" data-model="openai/gpt-5-mini"></script>

Set a spending limit at your provider: anyone who can open your site can use your proxy.

Each visitor brings their key

Without data-endpoint, the first question opens the AI settings: the visitor picks a provider and a model, pastes a key, tests it and saves. llm-connect encrypts the key with AES-GCM under a key the page cannot export, keeps it in the browser (for the session, or on the device if the visitor asks) and sends it only to the chosen provider. The visitor can also point the widget at Ollama or LM Studio on their own machine.

The browser calls the provider directly, so the provider must accept calls from web pages (CORS): OpenAI, Anthropic, Google, Mistral, OpenRouter, Groq, Together, DeepInfra, xAI and local servers with CORS enabled do.

Headless

import { createMurmur } from "murmur-rag";
import { anthropic } from "@ai-sdk/anthropic";

const murmur = createMurmur({ index, model: anthropic("claude-sonnet-5-5"), language: "en" });
const answer = await murmur.ask("What does the Pro plan include?");
for await (const part of answer.textStream) process.stdout.write(part);
const { cited } = await answer.done; // numbers of the passages it cites

Your own retriever

Any object with search(query, { limit, budgetTokens }) returning passages replaces BM25: an embeddings index, a search API, a database.

const retriever = {
  async search(query) {
    const hits = await mySearch(query);
    return hits.map((h) => ({ doc: 0, url: h.url, title: h.title, heading: "", anchor: "", text: h.text }));
  },
};
mountMurmur({ retriever, llm: { endpoint: "https://proxy.example/v1" } });

Styling and events

The widget lives in a Shadow DOM, so your CSS cannot break it and its CSS cannot leak into your page. Restyle it through custom properties on murmur-chat:

murmur-chat {
  --murmur-accent: #0b5cad;
  --murmur-accent-ink: #ffffff;
  --murmur-font: "Inter", sans-serif;
  --murmur-radius: 12px;
  --murmur-z: 1000;
}

It sends a murmur:state event at each step (searching, streaming, done, error) with the passages found and the ones cited: the switchboard on the home page is drawn from it.

document.querySelector("murmur-chat").addEventListener("murmur:state", (e) => {
  console.log(e.detail.state, e.detail.passages, e.detail.cited);
});

Privacy and security

  • murmur has no server and collects nothing. The question and the matching passages go to the AI provider you or the visitor chose, and nowhere else.
  • The conversation is kept in the tab (sessionStorage) so it survives a click on a source; it is gone when the tab closes.
  • Answers are rendered as text: model output never becomes HTML in your page, and links are limited to http, https and relative URLs.
  • Passages are sent to the model as quoted data with an instruction never to follow orders found inside them.

FAQ

Does it work on GitHub Pages?

Yes: murmur is static files. This site is on GitHub Pages and its bubble answers from its own index, built in its deployment workflow.

Which model should I use?

A fast, inexpensive model is enough: the work is reading a few passages and summarising them. The settings suggest the recommended model of each provider.

What if the answer is not on my site?

The assistant is told to say so and point to where to look, rather than invent. If no passage matches the question at all, it is told that nothing was found.

Can I use the search without AI?

Yes: bm25Retriever(index).search(query) from murmur-rag/rag returns the matching passages with their links, to build a plain site search.
